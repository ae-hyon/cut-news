# PR 생성

현재 브랜치의 전체 변경사항과 커밋 히스토리를 분석하여 한국어 제목과 구조화된 본문으로 GitHub PR을 생성한다.

## PR 제목

- 한국어로 작성
- 70자 이내
- 변경의 핵심만 요약 (세부 사항은 본문에)

## PR 본문 구조

```markdown
## 요약
- 이 PR이 해결하는 문제나 추가하는 기능을 1~3줄로 설명

## 변경 사항
- 주요 변경 내용을 bullet point로 나열
- 어떤 파일/모듈이 어떻게 바뀌었는지

## 테스트
- [ ] 테스트 방법이나 확인 사항 체크리스트
```

## 실행 절차

1. **현재 상태 파악** (병렬 실행)
   - `git status`로 커밋되지 않은 변경 확인
   - `git diff`로 staged/unstaged 변경 확인
   - 리모트 브랜치 추적 여부와 push 필요 여부 확인
   - `git log main..HEAD --oneline`과 `git diff main...HEAD`로 base 브랜치 대비 전체 변경 확인

2. **분석 및 초안 작성**
   - PR에 포함될 모든 커밋을 분석 (최신 커밋만이 아님)
   - 변경의 목적과 영향 범위 파악
   - 한국어 제목과 본문 초안 작성

3. **PR 생성**
   - 커밋되지 않은 변경이 있으면 먼저 커밋할지 사용자에게 확인
   - 필요하면 `git push -u`로 리모트에 push
   - `gh pr create`로 PR 생성 (HEREDOC으로 본문 전달)

4. **결과 공유**
   - PR URL을 사용자에게 전달

## 주의사항

- main/master 브랜치에 force push하지 않는다
- push 전에 리모트 브랜치 상태를 확인한다
- 사용자가 명시적으로 요청하지 않은 한 자동으로 push하지 않는다
